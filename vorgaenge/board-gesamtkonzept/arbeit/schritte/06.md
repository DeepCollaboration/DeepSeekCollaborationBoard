# Schritt 06 — Jedes Vorhaben nennt seinen Verantwortlichen

- **Ziel:** An jedem Vorhaben steht, wer gerade verantwortet; nur dieser Person
  werden die Handlungen angeboten.
- **Eingang:**
  - `vorgaenge/<ordner>/vorhaben.json` mit `verantwortliche`, `regel`,
    `rueckkehr` (Schritt 03);
  - `personen/*.json` (Schritt 03);
  - `produkt/index.js`, `produkt/ablage.js`, `produkt/client.js`;
  - `architektur.md`, Abschnitte „Daten und Besitz“, „Rechte und Sicherheit“,
    „Ablage im Repository“ (`verantwortliche`, `regel`).
- **Tun:**
  1. Einmalige Übernahme: In den fünf heutigen Vorhaben `verantwortliche` auf die
     eigene Person setzen — Schlüssel ist die Station, an der das Vorhaben steht,
     Wert `["p1"]`; `regel` bleibt `"einer"`. Diese Eintragung ist die Übernahme;
     sie wird im Bericht genannt.
  2. Eine Stelle im Host, die über Handlungen entscheidet, etwa `darf(vorhaben,
     aktion, person)`; Aktionen sind `aendern`, `verschieben`, `weitergeben`,
     `zurueckschicken`. Verantwortlich ist, wer an der Station des Vorhabens
     eingetragen ist; bei mehreren gilt `regel` (`einer` oder `alle`). Was später
     dazukommt (annehmen, Rücksprung, Beiträge), geht durch dieselbe Stelle.
  3. `/board/data` liefert je Vorhaben `verantwortliche`, `regel`, den Namen der
     Verantwortlichen (`verantwortet`) und `darf` mit den vier Aktionen.
  4. Die schreibenden Routen am Vorhaben prüfen dieselbe Stelle und antworten bei
     fehlender Berechtigung mit 403. Das gilt für `/board/vorhaben/aendern`,
     `/board/vorhaben/verschieben`, `/board/vorhaben/abzweigen`,
     `/board/vorhaben/zurueckschicken`.
  5. Anlegen: Wer ein Vorhaben anlegt, ist an dessen erster Station verantwortlich.
  6. Weitergeben: eine Handlung am Vorhaben, die Zielstation und nächste
     verantwortliche Person nennt; sie trägt `verantwortliche[<zielstation>]` ein
     und verschiebt das Vorhaben dorthin. Ohne Eintrag bleibt es beim Abgebenden.
  7. Die Seite zeigt „verantwortet von ‹Name›“ am Vorhaben; die Handlung
     „Weitergeben“ erscheint nur, wenn `darf.weitergeben` wahr ist. Ein fremdes
     Vorhaben erscheint mit seinem Namen an seiner Station und ohne
     „Weitergeben“.
  8. Prüfskript `produkt/test/schritt06.mjs` auf einer Ablage-Kopie:
     - das eigene Vorhaben hat `verantwortet: "Thomas Heinrich"` und
       `darf.weitergeben: true`;
     - ein fremdes Vorhaben (Verantwortliche `p2`, Station im Workflow von `p2`)
       erscheint mit `verantwortet: "Zweite Person"` und `darf.weitergeben: false`;
     - `POST /board/vorhaben/verschieben` auf das fremde Vorhaben antwortet 403;
     - Weitergeben des eigenen Vorhabens an eine Zielstation mit `p2` schreibt
       `verantwortliche[<zielstation>] = ["p2"]` und verschiebt es; danach ist
       `darf.weitergeben` für `p1` falsch;
     - ein neu angelegtes Vorhaben trägt den Anlegenden an seiner Station.
  9. Die Prüfskripte 02–05 grün halten.
  10. Am Ende den Stand der Ablage als Fassung festhalten („Verantwortliche“).
- **Ergebnis:** gefüllte `verantwortliche` in allen fünf Vorhaben; die eine
  Prüfstelle; `verantwortet` und `darf` in `/board/data`; 403 auf fremde
  Handlungen; Weitergeben mit Eintrag; Anzeige und Handlung in der Seite; ein
  Prüfskript; eine Fassung.
- **Prüfung:**
  ```
  node .../produkt/test/schritt06.mjs   # Exit 0
  node .../produkt/test/schritt05.mjs   # Exit 0
  node .../produkt/test/schritt04.mjs   # Exit 0
  node .../produkt/test/schritt03.mjs   # Exit 0
  node .../produkt/test/schritt02.mjs   # Exit 0
  python3 -c "…"  # jedes der fünf vorhaben.json hat verantwortliche mit p1 an seiner position
  git -C /workspace/projekte/board status --porcelain          # leer
  git -C /workspace/projekte/board log -1 --format='%an %s'    # Thomas Heinrich, Verantwortliche
  ```
- **Grenzen:** Kein Neustart, kein Netz. Die echte Ablage bekommt nur die
  Verantwortlichen-Einträge, keine zweite Person und kein fremdes Vorhaben — die
  leben in der Prüfkopie. Keine fremden Dateien außerhalb von `produkt/` und
  `arbeit/` ändern. Keine Rückfrage.
