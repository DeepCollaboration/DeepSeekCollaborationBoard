# Schritt 08 — Eine Station in einen Workflow stellen

- **Ziel:** Eine Station aus der Bibliothek kommt als Verweis in den Workflow des offenen Boards; das Workflow-Repository bekommt eine neue Position und, wo es passt, eine Kante; die Stationsdatei und das Board-Repository bleiben unberührt.
- **Eingang:**
  - `/workspace/projekte/board-plugin/komposition.js` (Board-Verweise, Workflow, Schritte), `index.js` (`/board/data`, `datenAntwort`, `git`, `autorMensch`, `AKTIV`), `formate/workflow.js` (Schreiben), `formate/station.js` (Name, Host, Fassung), `repos.js`, `abgleich.js`.
  - `client.js`: Bibliothek (drei Abschnitte), `data.schritte`, `S.bib*`, `poste`, `lade`/`neuLaden`.
  - `test/schritt25.mjs` (Server, eigenes `DSH_HOME`, Testboard), `werkzeuge/pruefflaeche.mjs`.
  - `architektur.md`, Abschnitte „Workflow“, „Formate“ (`workflow.json`), „Daten und Besitz“ (feste Fassung); `bauplan.md`, Schritt 8.
- **Tun:**
  1. `komposition.js`: neben `schritte` (Stationen im Workflow) ein Feld `stationen` mit allen Stationen, auf die das Board verweist (`board.json.stationen`): `{ id, name, host, fassung, repo, imWorkflow }`; fehlt ein Repository oder die Datei, steht der Eintrag mit `fehlt: true` und ohne erfundenen Namen. Fassung aus dem Verweis, sonst leer.
  2. Neue Route `POST /board/workflow/station` (Fassung 2): `{ station }` (Kennung) oder `{ repo }`; das offene Board und seinen Workflow bestimmen; die Station in `board.json.stationen` suchen; `workflow.json` lesen; den Stationsverweis aufnehmen, wenn er fehlt (mit `repo` und `fassung`; fehlt die Fassung, den letzten Tag oder `HEAD` des Stations-Repositories eintragen); eine neue Position mit freier Kennung (`<station>-2`, `<station>-3` …) und einer freien Stelle anlegen; hat die letzte Position keine ausgehende Kante, eine Kante von ihr zur neuen Position schreiben; `workflow.json` atomar schreiben und **nur diese Datei** im Workflow-Repository committen (Autor aus der Identität, deutsche Nachricht). Kein Push (Schritt 05), kein Schreiben in Station, Vorhaben oder Board. Antwort: das neu zusammengesetzte Board.
  3. Die Route weist ab: unbekannte Station → 404, kein Workflow-Repository → 409, Stations-Repository fehlt → 404; in keinem Fall ein Commit. Fassung 1 unverändert.
  4. `client.js`: im Abschnitt „Stationen“ der Bibliothek (Fassung 2) steht an jeder Station ein kleiner Knopf „+ Workflow“ (Titel: „Diese Station in den Workflow stellen; eine zweite Position ist erlaubt“); er ruft die Route, wartet auf die Antwort und zeigt das neue Board; der Klick auf den Stationsnamen öffnet weiter die Station. Kein neuer Bildschirm.
  5. `test/schritt26.mjs` (neu): eigene Prüffläche unter `/tmp/board-scheibe1/schritt26`; das Testboard; eine dritte Station `station-pruefen` als Kopie von `station-idee` mit eigener `station.json` (id `pruefen`, Name „Prüfen“) und einem Commit, im `board.json` als Verweis aufgenommen; Testboard verbinden; `GET /board/data` zeigt `stationen` mit drei Einträgen, „Prüfen“ mit `imWorkflow: false`; `POST /board/workflow/station` mit `{ station: 'pruefen' }` → 200; `git -C workflow log -1 --name-only` nennt nur `workflow.json`; `workflow.json` trägt den Verweis auf `station-pruefen`, eine neue Position und eine Kante von der letzten Position; die HEADs von `station-pruefen`, `station-idee`, `station-umsetzen`, `vorhaben` und `board` sind unverändert; `/board/data` zeigt die neue Position und `imWorkflow: true`; eine unbekannte Station → 404 ohne neuen Commit. Danach Server, Ablage und Home entfernen.
