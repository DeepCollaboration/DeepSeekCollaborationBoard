# Schritt 07 — Ein fremdes Vorhaben steht auf meinem Board und lässt sich lesen

- **Ziel:** Fremde Vorhaben sind sichtbar, anklickbar und lesbar; sie gehören nicht
  mir, also ändert sich an ihnen nichts. Gezeigt wird nur, was im Ordner liegt.
- **Eingang:**
  - `vorgaenge/<ordner>/vorhaben.json` aller Personen (Schritt 03);
  - `verantwortliche` und die Prüfstelle `darf` (Schritt 06);
  - `produkt/index.js` (Routen `/board/dateien`, `/board/doc`,
    `/board/doc/schreiben`), `produkt/ablage.js`, `produkt/client.js`;
  - `architektur.md`, Abschnitte „Ablage im Repository“ und „Daten und Besitz“.
- **Tun:**
  1. Der Host liest alle `vorgaenge/*/vorhaben.json`, nicht nur die eigenen. Das
     ist der Fall, sobald der Ordner im Repository liegt — unabhängig davon, wer
     verantwortet.
  2. Ein Vorhaben trägt in `/board/data` die Farbe seiner verantwortlichen Person,
     wenn es keine eigene `farbe` hat; der Name des Verantwortlichen steht dabei
     (`verantwortet`).
  3. Lesen: `/board/dateien` und `/board/doc` arbeiten für fremde Vorhaben wie für
     eigene. Die Dateiliste zeigt, was im Ordner liegt — einschließlich
     `transkripte/`, nichts Erfundenes.
  4. Schreiben: `/board/doc/schreiben` prüft `darf(vorhaben, "aendern", person)`
     und antwortet ohne Berechtigung mit 403, bevor irgendetwas geschrieben wird.
     Dasselbe gilt für alle Routen, die in einen Vorhabenordner schreiben
     (Vorhaben ändern, Dateien anlegen, Stationen setzen).
  5. Die Seite bietet an einem fremden Vorhaben: Öffnen, Lesen, die Dateien
     ansehen. Sie bietet nicht: Umbenennen, Ziehen, Weitergeben, Speichern,
     Anlegen. Der Leser eines fremden Vorhabens zeigt den Text ohne
     Bearbeitungsfeld.
  6. Prüfskript `produkt/test/schritt07.mjs` auf einer Ablage-Kopie mit `p2` und
     einem fremden Vorhaben (`vorgaenge/von-p2/idee.md`, `vorhaben.json` mit
     Verantwortlicher `p2` an einer Station im Workflow von `p2`):
     - das fremde Vorhaben erscheint an seiner Station, mit `verantwortet:
       "Zweite Person"` und einer Farbe, die zur Person gehört;
     - `GET /board/dateien` listet `idee.md` (und keine erfundene Datei);
     - `GET /board/doc` liefert den Text von `idee.md`;
     - `POST /board/doc/schreiben` auf `idee.md` antwortet 403, die Datei bleibt
       byte-gleich;
     - das eigene Vorhaben bleibt schreibbar (Gegenprobe).
  7. Die Prüfskripte 02–06 grün halten.
  8. Am Ende den Stand der Ablage als Fassung festhalten („Fremde Vorhaben lesen“).
- **Ergebnis:** fremde Vorhaben vollständig lesbar; Farbe und Verantwortlicher
  sichtbar; Schreiben überall mit derselben Prüfung abgewiesen; ein Prüfskript;
  eine Fassung.
- **Prüfung:**
  ```
  node .../produkt/test/schritt07.mjs   # Exit 0
  node .../produkt/test/schritt06.mjs   # Exit 0
  node .../produkt/test/schritt05.mjs   # Exit 0
  node .../produkt/test/schritt04.mjs   # Exit 0
  node .../produkt/test/schritt03.mjs   # Exit 0
  node .../produkt/test/schritt02.mjs   # Exit 0
  grep -n 'darf' .../produkt/client.js | head    # fremde Vorhaben ohne Handlungen
  git -C /workspace/projekte/board status --porcelain          # leer
  git -C /workspace/projekte/board log -1 --format='%an %s'    # Thomas Heinrich, Fremde Vorhaben lesen
  ```
- **Grenzen:** Kein Neustart, kein Netz. Die echte Ablage bekommt kein fremdes
  Vorhaben und keine zweite Person — beides lebt in der Prüfkopie. Keine fremden
  Dateien außerhalb von `produkt/` und `arbeit/` ändern. Keine Rückfrage.

Am Ende: Bericht nach `arbeit/schritte/07-bericht.md` — was gebaut, welche Dateien,
welcher Befehl, Exit-Code, entscheidende Zeile.
