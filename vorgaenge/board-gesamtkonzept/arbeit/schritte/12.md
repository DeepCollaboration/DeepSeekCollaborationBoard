# Schritt 12 — Der Verantwortliche entscheidet über den Beitrag

- **Ziel:** Der Verantwortliche nimmt einen Beitrag an, lehnt ihn ab oder nimmt
  Teile; erst dann ändert sich sein Stand. Der Beitrag bleibt mit dem Entscheid
  sichtbar.
- **Eingang:**
  - ein Beitrag in `beitraege/` (Schritt 11);
  - Verantwortliche und Prüfstelle `darf` (Schritt 06);
  - `produkt/index.js`, `produkt/ablage.js`, `produkt/client.js`;
  - `architektur.md`, Abschnitte „Ablage im Repository“ (`entschieden`) und
    „Daten und Besitz“.
- **Tun:**
  1. Neue Route `POST /board/beitrag/entscheiden`:
     `{ beitrag, art: "annehmen" | "ablehnen", teile? }` → `{ ok, beitrag }`.
     Sie prüft zuerst, dass die eigene Person das Vorhaben verantwortet
     (`darf(…, "entscheiden", …)`; die Prüfstelle aus Schritt 06 bekommt die
     Aktion `entscheiden`) und antwortet sonst 403.
  2. Annehmen schreibt jede vorgeschlagene Datei aus
     `beitraege/<vorhaben>/<beitrag>/<datei>.md` in den Ordner des Vorhabens
     (`vorgaenge/<ordner>/<datei>`), hält das als neue Fassung mit dem eigenen
     Urheber fest und trägt `entschieden = { von, am, art: "angenommen", teile }`
     in die Beitragsdatei ein. `teile` ist die Liste der übernommenen Dateinamen;
     ohne Angabe werden alle übernommen.
  3. Ablehnen schreibt keine Vorhabendatei und trägt
     `entschieden = { von, am, art: "abgelehnt", teile: [] }` ein. Der Stand des
     Vorhabens bleibt unverändert.
  4. Ein bereits entschiedener Beitrag wird nicht noch einmal entschieden (409).
     Ein Beitrag, der nicht existiert, antwortet 404.
  5. `/board/data` liefert an jedem Beitrag `entschieden` mit; die Seite zeigt den
     Entscheid (wer, wann, angenommen/abgelehnt, welche Teile) und bietet die
     Handlungen nur dem Verantwortlichen an.
  6. Prüfskript `produkt/test/schritt12.mjs` auf einer Ablage-Kopie, Modul als
     `p1`, mit drei Beiträgen an einem eigenen Vorhaben:
     - Beitrag A mit einer Datei `vision.md`: annehmen → die Datei im Vorhaben
       trägt den vorgeschlagenen Text, `entschieden.von` ist „p1“, `am` gültig,
       `art` „angenommen“, die Fassung nennt „Thomas Heinrich“, der Beitrag und
       seine Datei bleiben liegen;
     - Beitrag B mit zwei Dateien `a.md` und `b.md`, nur `a.md` übernehmen →
       `a.md` geändert, `b.md` unverändert, `entschieden.teile = ["a.md"]`;
     - Beitrag C ablehnen → keine Vorhabendatei geändert, `art` „abgelehnt“;
     - ein zweiter Entscheid auf A → 409; ein Entscheid auf das Vorhaben einer
       anderen Person → 403;
     - der Verlauf des Vorhabens zeigt nach dem Annehmen eine neue Fassung.
  7. Die Prüfskripte 02–11 grün halten.
  8. Am Ende den Stand der Ablage als Fassung festhalten („Beitrag entschieden“).
- **Ergebnis:** die Route `/board/beitrag/entscheiden`; `entschieden` in den
  Beitragsdateien; übernommene Dateien als neue Fassung; Teile und Ablehnung;
  Anzeige und Handlungen für den Verantwortlichen; ein Prüfskript; eine Fassung.
- **Prüfung:**
  ```
  node .../produkt/test/schritt12.mjs   # Exit 0
  node .../produkt/test/schritt11.mjs   # Exit 0
  node .../produkt/test/schritt06.mjs   # Exit 0
  node .../produkt/test/schritt03.mjs   # Exit 0
  ls /workspace/projekte/board/beitraege 2>/dev/null   # echte Ablage ohne Beiträge
  git -C /workspace/projekte/board status --porcelain          # leer
  git -C /workspace/projekte/board log -1 --format='%an %s'    # Thomas Heinrich, Beitrag entschieden
  ```
- **Grenzen:** Kein Neustart, kein Netz. Die echte Ablage bekommt keinen Beitrag
  und keine zweite Person — beides lebt in der Prüfkopie. Keine fremden Dateien
  außerhalb von `produkt/` und `arbeit/` ändern. Keine Rückfrage.

Am Ende: Bericht nach `arbeit/schritte/12-bericht.md` — was gebaut, welche Dateien,
welcher Befehl, Exit-Code, entscheidende Zeile.
