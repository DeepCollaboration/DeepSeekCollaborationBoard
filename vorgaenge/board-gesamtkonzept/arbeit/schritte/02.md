# Schritt 02 — Die Ablage ist ein eigenes Repository mit meiner Person

- **Ziel:** Das Board kennt seine Person und seine Ablage: `produkt/board.config.json`
  mit `{ person, repo }`; `projekte/board/` ist ein eigenes Git-Repository; jede
  Speicherung des Boards ist eine Fassung mit Urheber; der Arbeitsbereich führt die
  Ablage nicht mehr in seiner eigenen Geschichte mit.
- **Eingang:**
  - `produkt/` (Schritt 01), insbesondere `index.js` (Konstanten `BOARD_DIR`,
    `DATA_PATH`, `VORGANG_DIR`, `REPO`, `AUTOR_MENSCH`, `AUTOR_MODELL` und
    `festhalten`).
  - `/workspace/projekte/board/` mit `board.json` und `vorgaenge/`.
  - `architektur.md`, Abschnitte „Ablage im Repository“ (Kopf), „Git“ und
    „Harness“ (Eigene Person und Ablage).
- **Tun:**
  1. Die eigene Person aus dem heutigen Board ableiten: in
     `/workspace/projekte/board/board.json` die Person mit `ich: true` (derzeit
     `p1`, „Thomas Heinrich“). Keinen Namen erfinden; fehlt die Person, abbrechen
     und das berichten.
  2. `produkt/board.config.json` anlegen: `{ "person": "<kennung>", "repo":
     "/workspace/projekte/board" }`. Das Plugin liest die Datei relativ zu sich
     (`import.meta.url`), damit eine Kopie des Produkts ihre eigene Konfiguration
     liest. Fehlt sie, soll das Plugin nicht abstürzen, sondern im Protokoll sagen,
     dass keine Konfiguration da ist.
  3. In `produkt/index.js` die Ablage-Pfade aus der Konfiguration nehmen
     (`BOARD_DIR`, `DATA_PATH`, `VORGANG_DIR`, `REPO`); `SKILL_DIR` und
     `SESSION_DIR` bleiben `$DSH_HOME`. Urheber: die eigene Person mit ihrem Namen,
     bei Modellläufen `Modell (<Name>)`. Keine festen Ablage-Pfade mehr im Code.
  4. In `/workspace/projekte/board/`: `git init -b main`, `.gitignore` mit
     `vorgaenge/*/produkt/` und `*.tmp` (das Produkt gehört nicht in die Ablage),
     alles Übrige aufnehmen und mit dem Urheber „Thomas Heinrich“ als erste Fassung
     festhalten.
  5. Den Arbeitsbereich lösen: `projekte/board/` in `/workspace/.gitignore`
     aufnehmen, `git -C /workspace rm -r --cached projekte/board`, und das als
     Fassung festhalten („Ablage aus dem Arbeitsbereich gelöst“). Die Dateien
     bleiben auf der Platte. Das ist die eine Ausnahme von „keine eigenen
     Commits“; der Bauplan verlangt sie, der Bericht nennt sie.
  6. Prüfskript `produkt/test/schritt02.mjs`: kopiert `produkt/` nach `/tmp`,
     schreibt dort eine `board.config.json` mit einem Prüf-Repository, lädt das
     Modul mit einem minimalen ctx (`webServer.register` sammelt die Handler,
     `effect` führt aus, `get` liefert `undefined`), ruft eine schreibende Route
     auf und prüft den Urheber der entstandenen Fassung im Prüf-Repository. Die
     echte Ablage wird dabei nicht angefasst.
- **Ergebnis:** `produkt/board.config.json`; `produkt/test/schritt02.mjs`;
  `/workspace/projekte/board/.git` mit erster Fassung; das Modul schreibt und
  festschreibt über die Konfiguration; `/workspace` führt die Ablage nicht mehr.
- **Prüfung:**
  ```
  test -f /workspace/projekte/board/vorgaenge/board-gesamtkonzept/produkt/board.config.json
  git -C /workspace/projekte/board log --format='%an %s' | head -3
  git -C /workspace/projekte/board ls-files | grep -c 'produkt/'        # muss 0 sein
  node /workspace/projekte/board/vorgaenge/board-gesamtkonzept/produkt/test/schritt02.mjs
  git -C /workspace status --porcelain | grep 'projekte/board'          # muss leer sein
  curl -s -o /dev/null -w '%{http_code}' "$DSH_WEB_URL/board/data"      # muss 200 sein
  ```
  Erwartet: Konfigurationsdatei vorhanden; die erste Fassung nennt „Thomas
  Heinrich“; keine Datei aus `produkt/` in der Ablage; das Prüfskript endet mit
  Exit 0 und der Urheber im Prüf-Repository ist „Thomas Heinrich“; der
  Arbeitsbereich zeigt nichts mehr unter `projekte/board`; das laufende Board
  antwortet weiter.
- **Grenzen:** Das laufende Board nicht neu starten (er würde diese Sitzung
  beenden). `board.json` inhaltlich nicht ändern, keine Vorhaben umschreiben.
  Keine anderen Dateien außerhalb von `produkt/`, `/workspace/projekte/board/` und
  den zwei Stellen in `/workspace` (`.gitignore`, Index) anfassen. Keine
  Rückfrage.
- **Hinweis zur Wirkung:** Das laufende Board schreibt bis zum nächsten Neustart
  weiter mit dem alten, geladenen Modul. Es schreibt Dateien weiterhin, hält sie
  nach dem Schnitt aber nicht mehr in `/workspace` fest — das ist erwartet.

Am Ende: Bericht nach `arbeit/schritte/02-bericht.md` — was gebaut, welche Dateien,
welcher Befehl, Exit-Code, entscheidende Zeile.
