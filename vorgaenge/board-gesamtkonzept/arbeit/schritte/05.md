# Schritt 05 — Der Workflow der anderen Person steht auf meinem Board

- **Ziel:** Das Board zeigt die Workflows aller Personen; fremde Schritte tragen den
  Namen ihres Hosts und werden nicht kopiert. Die eigene Fläche steht zuerst.
- **Eingang:**
  - `workflows/p1.json`, `personen/p1.json` (Schritt 03);
  - `produkt/index.js`, `produkt/ablage.js`, `produkt/client.js`;
  - Abgleich (Schritt 04);
  - `architektur.md`, Abschnitte „Ablage im Repository“ (workflows) und
    „Schnittstellen: HTTP-Routen“ (`/board/data`).
- **Tun:**
  1. Der Host liest alle `workflows/*.json` und `personen/*.json`. `/board/data`
     liefert `workflows`: eine Liste je Person, die eigene Person zuerst; je
     Eintrag `{ id, name, farbe, ich, workflows: [...] }`. Die Schlüssel `workflow`
     und `schritte` der bisherigen Antwort entfallen; `personen`, `vorgaenge`,
     `einstellungen` und `stand` bleiben.
  2. Ein fremder Schritt trägt `host` = fremde Person und wird in der Antwort als
     nicht bearbeitbar gekennzeichnet (etwa `fremd: true`). Geändert werden kann er
     nur in der Workflow-Datei seines Hosts.
  3. Ein Schritt kann in einem Workflow als Verweis stehen:
     `{ ref: "<person>/<workflow>/<schritt>" }`. Der Host löst ihn zum Anzeigen auf
     (Name, Host, Eingang, Ausgang), ohne den Schritt zu kopieren. Fehlt das Ziel,
     wird der Verweis als fehlend gezeigt — kein geratener Schritt.
  4. Die Seite zeigt eine Fläche je Person, die eigene zuerst, jede mit Namen und
     Farbe. In der fremden Fläche sind die Schritte sichtbar und anklickbar; ein
     Klick zeigt Ein- und Ausgang. Felder zum Ändern, Löschen, Anlegen oder Ziehen
     gibt es dort nicht. Die eigene Fläche behält ihre Bedienung.
  5. Die persönlichen Einstellungen und die Gesprächsverweise bleiben, wo sie sind;
     die Seite findet sie wie bisher.
  6. Prüfskript `produkt/test/schritt05.mjs`: Ablage-Kopie, zweite Person `p2`
     („Zweite Person“) mit `personen/p2.json` und `workflows/p2.json` mit zwei
     Schritten, Host `p2`, dazu ein Verweis im eigenen Workflow auf einen
     p2-Schritt. Geprüft wird:
     - `workflows` hat zwei Einträge, der eigene steht zuerst, `ich` ist nur beim
       eigenen wahr;
     - die zwei fremden Schritte tragen `host: "p2"` und sind als fremd markiert;
     - der Verweis erscheint aufgelöst mit Namen und Host, ohne die Datei von p2 zu
       verändern;
     - ohne die p2-Dateien hat `workflows` genau einen Eintrag;
     - `workflows/p1.json` ist vor und nach dem Lesen byte-gleich.
  7. Die Prüfskripte der Schritte 03 und 04 an die neue Antwort anpassen und grün
     halten.
  8. Am Ende den Stand der Ablage als Fassung festhalten („Fremde Workflows“).
- **Ergebnis:** `/board/data` mit `workflows` je Person; fremde Schritte markiert
  und in der Seite lesbar; Verweise werden aufgelöst, nicht kopiert; ein Prüfskript
  belegt beides; eine Fassung.
- **Prüfung:**
  ```
  node .../produkt/test/schritt05.mjs   # Exit 0
  node .../produkt/test/schritt04.mjs   # Exit 0
  node .../produkt/test/schritt03.mjs   # Exit 0
  grep -n 'workflows' .../produkt/index.js | head
  grep -n 'fremd' .../produkt/client.js | head
  git -C /workspace/projekte/board status --porcelain   # leer
  git -C /workspace/projekte/board log -1 --format='%an %s'  # Thomas Heinrich, Fremde Workflows
  ```
- **Grenzen:** Kein Neustart. Kein Netz. Die echten Workflow-Dateien nicht mit einer
  zweiten Person beschmutzen — die zweite Person lebt nur in der Prüfkopie. Keine
  fremden Dateien außerhalb von `produkt/` und `arbeit/` ändern. Keine Rückfrage.

welcher Befehl, Exit-Code, entscheidende Zeile.
