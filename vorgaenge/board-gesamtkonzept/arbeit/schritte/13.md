# Schritt 13 — Zweig und Fork tragen ihre Herkunft

- **Ziel:** Ein Vorhaben, das aus einem anderen entstanden ist, sagt es; das
  Original bleibt, wie es war.
- **Eingang:**
  - `fork_von`, `zweig_von` in `vorgaenge/<ordner>/vorhaben.json` (Schritt 03;
    zwei Zweige tragen schon `zweig_von`);
  - die heutige Handlung „Abzweigen“ (`/board/vorhaben/abzweigen`);
  - `produkt/index.js`, `produkt/ablage.js`, `produkt/client.js`;
  - `architektur.md`, Abschnitte „Ablage im Repository“ (`fork_von`,
    `zweig_von`) und „Daten und Besitz“ (Fork, Branch).
- **Tun:**
  1. Abzweigen schreibt am neuen Vorhaben
     `zweig_von = { von: <kennung des ursprungs>, station: <station des
     ursprungs>, datum }`. Der Ursprung bleibt in Dateien und Station unverändert;
     der Zweig bekommt eine Kopie der Dateien im Stand des Abzweigens.
  2. Forken: eine Handlung an jedem sichtbaren Vorhaben, auch an einem fremden.
     Sie legt einen eigenen Ordner an, der die Dateien des Ursprungs im
     augenblicklichen Stand übernimmt, trägt `fork_von = <kennung des ursprungs>`,
     übernimmt die Station und setzt die eigene Person als verantwortlich. Die
     Läufe des Ursprungs gehören nicht zum Fork. Die fremde Datei und der fremde
     Ordner werden nicht geschrieben.
  3. `/board/data` liefert je Vorhaben `fork_von` und `zweig_von` samt den Namen
     der Ursprünge (für die Anzeige), ohne dass die Seite sie nachschlagen muss.
  4. Die Seite zeigt am Vorhaben „Zweig von ‹Name› ab ‹Station›“ und
     „Fork von ‹Name›“; die Herkunft ist anklickbar, wenn der Ursprung sichtbar
     ist.
  5. Prüfskript `produkt/test/schritt13.mjs` auf einer Ablage-Kopie mit `p2` und
     einem fremden Vorhaben `von-p2` (Datei `idee.md`):
     - ein Zweig des eigenen Vorhabens entsteht mit `zweig_von` (Ursprung,
       Station, Datum); der Ursprung ist in Dateien und Station byte-gleich; der
       Zweig trägt die Dateien des Ursprungs;
     - ein Fork des fremden Vorhabens entsteht als eigenes Vorhaben mit
       `fork_von: "von-p2"`, der eigenen Person als Verantwortliche und den
       kopierten Dateien; `vorgaenge/von-p2/` ist byte-gleich;
     - `/board/data` nennt für beide die Namen der Ursprünge;
     - die Seite zeigt „Zweig von“ und „Fork von“ (`grep` im Quelltext genügt).
  6. Die Prüfskripte 02–12 grün halten.
  7. Am Ende den Stand der Ablage als Fassung festhalten („Herkunft“).
- **Ergebnis:** `zweig_von` beim Abzweigen, `fork_von` beim Forken (auch fremder
  Vorhaben), die Namen der Ursprünge in `/board/data`, die Anzeige am Vorhaben;
  das Original bleibt unverändert; ein Prüfskript; eine Fassung.
- **Prüfung:**
  ```
  node .../produkt/test/schritt13.mjs   # Exit 0
  node .../produkt/test/schritt12.mjs   # Exit 0
  node .../produkt/test/schritt07.mjs   # Exit 0
  node .../produkt/test/schritt03.mjs   # Exit 0
  git -C /workspace/projekte/board status --porcelain          # leer
  git -C /workspace/projekte/board log -1 --format='%an %s'    # Thomas Heinrich, Herkunft
  ```
- **Grenzen:** Kein Neustart, kein Netz. Die echte Ablage bekommt keinen neuen
  Zweig und keinen Fork und keine zweite Person — das lebt in der Prüfkopie. Die
  zwei vorhandenen Zweige in der echten Ablage bleiben unverändert. Keine fremden
  Dateien außerhalb von `produkt/` und `arbeit/` ändern. Keine Rückfrage.

welcher Befehl, Exit-Code, entscheidende Zeile.
