# Schritt 26 — Anmelden und dürfen

- **Ziel:** Das Board sagt, wer angemeldet ist und ob diese Person hier schreiben oder anlegen darf; ohne Token nennt es den Grund und den Weg, und lokales Schreiben bleibt möglich.
- **Eingang:** Schritt 25; `rechte.js` (`darfSchreiben`, `darfSchnell`-Gegenstück in `index.js`); `index.js` (`/board/data`, `/board/github/stand`); `github.js` (`liesToken`, `liesLogin`, `ich`, `berechtigung`); `client.js` (Board-Leiste, Einstellungen, GitHub-Abschnitt); `test/schritt14.mjs` und `test/schritt15.mjs` als Muster für einen nachgebildeten GitHub-Server.
- **Tun:**
  1. **Die Frage.** Das Schreibrecht wird als Frage nach der **Person** beantwortet, nicht als „Token liegt vor“: lokal ohne Remote → ja; Remote ohne Token → nein, weil niemand angemeldet ist; Remote mit Token → die Antwort von GitHub für den Login (`berechtigung`), nicht für den Token. Die vorhandene 30-Sekunden-Ablage bleibt je Repository, Remote und Login geschlüsselt.
  2. **Antwortform.** `/board/data` der Fassung 2 trägt zusätzlich `darfGrund` und `darfHinweis` (deutsche Sätze, nur wenn `darf` falsch ist) sowie `anlegen: { darf, grund, hinweis }` für neue Dinge unter dem Eigentümer. `darf` bleibt ein Wahrheitswert, damit die vorhandenen Prüfungen und die Seite weiterlaufen. Die Gründe unterscheiden: kein Token, Token ohne Schreibrecht, Recht nicht prüfbar (kein Netz). `anlegen.darf` ist ohne Token falsch und nennt den Weg; mit Token wahr (die tatsächliche Anlage prüft Schritt 27).
  3. **Stand.** `/board/github/stand` nennt weiter `verbunden` und `login`; ohne Token `login: null`, kein Fehler. Mit Token und ohne Netz bleibt der gemerkte Login stehen, `fehler` nennt den Grund. Kein neues Feld, das die Oberfläche nicht braucht.
  4. **Anzeige.** Ist `darf` falsch, steht in der Board-Leiste „Nur lesen“ mit `darfGrund`; darunter, falls vorhanden, `darfHinweis`. Schreibknöpfe (Weitergeben, Bearbeiten, Eigentümer speichern, Vorhaben-Handlungen) werden nicht angeboten, auch nicht ausgegraut. Ist `darf` wahr, steht nichts davon da. Der GitHub-Abschnitt zeigt „verbunden als <login>“ weiter; ohne Token bleibt sein Hinweis.
  5. **Prüfung.** `test/markt26.mjs`: eigenes Temp-Heim; (a) lokales Board ohne Remote → `darf: true`, kein Grund, Datei speichern geht; (b) Board mit GitHub-Remote ohne Token → `darf: false`, Grund nennt Token/Anmeldung, `anlegen.darf: false` mit Hinweis, `POST /board/einstellung` 403, `stand.login: null`; (c) nachgebildeter GitHub-Server + Token → `stand.login` gesetzt, `berechtigung: "write"` → `darf: true`, `"read"` → `darf: false` mit Grund „kein Schreibrecht“, Token löschen → wieder falsch. Kein echtes Netz; `DSH_GITHUB_API` zeigt auf den nachgebildeten Server.
  6. **Grenzen der Anzeige.** Kein neuer Schalter, kein „Torwächter“, keine Anlege-Route (Schritt 27). Die Anzeige ist über den Code und `node --check` belegt; ein Browserdurchgang gehört zur Abnahme.
- **Ergebnis:** `darf` mit Grund und Hinweis, `anlegen`-Antwort, „Nur lesen“ in der Leiste, keine Schreibknöpfe ohne Recht; `test/markt26.mjs` grün; Suite weiter grün.
- **Prüfung:** `cd /workspace/projekte/board-plugin && node --test test/markt26.mjs` → `ok Recht: lokal ja, Remote ohne Token nein mit Grund, Token write ja, read nein, anlegen`; danach `node --test` → 41 vorhandene plus der neue Test, 0 Fehler; `node --check index.js`, `node --check rechte.js`, `node --check client.js` → je 0.
- **Grenzen:** nur Produktordner und `test/markt26.mjs`; keine Rückfrage; keine eigenen Commits; kein echtes Netz.
