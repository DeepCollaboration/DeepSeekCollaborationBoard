# Schritt 09 — Mein Workflow enthält einen fremden Schritt

- **Ziel:** Ein fremder Schritt lässt sich in den eigenen Workflow stellen; er
  bleibt der Schritt seines Hosts. Ein Vorhaben kann auf ihm stehen.
- **Eingang:**
  - fremde Workflows (Schritt 05), aufgelöste Verweise `{ref}` (Schritt 05);
  - eigene Workflow-Datei `workflows/p1.json` (Schritt 03/08);
  - `produkt/index.js` (Routen `/board/schritt`, `/board/schritt/aendern`,
    `/board/schritt/loeschen`, `/board/positions`, `/board/position/platzieren`),
    `produkt/client.js`;
  - `architektur.md`, Abschnitte „Ablage im Repository“ (workflows, `ref`) und
    „Daten und Besitz“ (Der Schritt gehört seinem Host).
- **Tun:**
  1. Eine Handlung im Host, die einen fremden Schritt als Verweis in die eigene
     Workflow-Datei stellt: `workflows/p1.json` bekommt einen Schritt
     `{ ref: "<person>/<workflow>/<schritt>" }` samt Position. Die Datei der
     anderen Person wird nicht angefasst; der Schritt wird nicht kopiert.
  2. Der Verweis ist ein Teil des eigenen Workflows: er lässt sich dort auch wieder
     herausnehmen (eigene Fläche). Der fremde Schritt selbst lässt sich von hier
     aus nicht ändern und nicht löschen.
  3. Die Seite bietet das Anstellen eines fremden Schritts aus der fremden Fläche
     heraus an. Der Verweis erscheint in der eigenen Fläche mit Namen, Host („bei
     ‹Person›“) und Ein- und Ausgang; seine Einstellungen lassen sich nicht
     öffnen. Ist das Ziel verschwunden, erscheint der Verweis als fehlend.
  4. Ein Vorhaben kann auf der Verweis-Position stehen (anlegen, verschieben,
     verantworten). Es gehört weiter der eigenen Person.
  5. Prüfskript `produkt/test/schritt09.mjs` auf einer Ablage-Kopie mit `p2` und
     einem p2-Workflow mit Schritt `pruefen`:
     - der fremde Schritt wird in den eigenen Workflow gestellt;
     - `workflows/p1.json` trägt danach einen `ref`-Eintrag, `workflows/p2.json`
       ist byte-gleich;
     - `/board/data` löst den Verweis in der eigenen Fläche auf: Name „Prüfen“,
       `host: "p2"`, `fremd: true`, Ein- und Ausgang;
     - ein Vorhaben auf der Verweis-Position erscheint dort mit `verantwortet:
       "Thomas Heinrich"`;
     - ein Änderungsversuch am fremden Schritt (`/board/schritt/aendern`,
       `/board/schritt/loeschen`) antwortet 403;
     - nach dem Herausnehmen des Verweises ist die eigene Datei wieder ohne ihn,
       die fremde Datei unverändert.
  6. Die Prüfskripte 02–08 grün halten.
  7. Am Ende den Stand der Ablage als Fassung festhalten („Fremder Schritt“).
- **Ergebnis:** ein Verweis im eigenen Workflow, anstellbar und wieder entfernbar;
  der fremde Schritt bleibt unverändert; ein Vorhaben kann darauf stehen; ein
  Prüfskript; eine Fassung.
- **Prüfung:**
  ```
  node .../produkt/test/schritt09.mjs   # Exit 0
  node .../produkt/test/schritt08.mjs   # Exit 0
  node .../produkt/test/schritt07.mjs   # Exit 0
  node .../produkt/test/schritt05.mjs   # Exit 0
  node .../produkt/test/schritt03.mjs   # Exit 0
  python3 -c "…"  # workflows/p1.json ohne ref (echte Ablage)
  git -C /workspace/projekte/board status --porcelain          # leer
  git -C /workspace/projekte/board log -1 --format='%an %s'    # Thomas Heinrich, Fremder Schritt
  ```
- **Grenzen:** Kein Neustart, kein Netz. Die echte Ablage bekommt keinen
  fremden Schritt — der lebt in der Prüfkopie. Keine fremden Dateien außerhalb von
  `produkt/` und `arbeit/` ändern. Keine Rückfrage.

Am Ende: Bericht nach `arbeit/schritte/09-bericht.md` — was gebaut, welche Dateien,
welcher Befehl, Exit-Code, entscheidende Zeile.
