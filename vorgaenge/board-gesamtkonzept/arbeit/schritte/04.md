# Schritt 04 — Der Abgleich holt und gibt

- **Ziel:** Das Board hält seinen Stand mit dem Remote auseinander: es holt vor dem
  Lesen, gibt nach dem Schreiben und sagt, wie frisch der Stand ist. Ohne Remote
  oder ohne Netz öffnet es trotzdem und sagt, dass es nicht abgeglichen ist.
- **Eingang:**
  - `produkt/ablage.js` und `produkt/index.js` (Schritt 03);
  - `produkt/client.js` (die Kopfzeile);
  - `/workspace/projekte/board` als Repository (Schritt 02/03), **ohne** Remote;
  - `architektur.md`, Abschnitte „Git“ und „Ausfälle und Betrieb“.
- **Tun:**
  1. Abgleich über `git` gegen den in `.git/config` eingetragenen `origin`:
     `git -C <repo> fetch --prune origin`, dann den eigenen Zweig auf den fremden
     Stand legen (`pull --rebase`), dann `git -C <repo> push origin main`. Kein
     neuer Remote im echten Repository; der Abgleich arbeitet mit dem, was da ist.
  2. Neue Route `POST /board/sync` (`{}` → `{ geholt, gegeben, lage }`). Sie holt,
     legt die eigenen Fassungen darauf und gibt sie weiter.
  3. `stand` in `/board/data`: `{ zeit, nur_lokal, remote, lage }`.
     `zeit` ist der Zeitpunkt des letzten erfolgreichen Abgleichs (ISO-Zeichenkette
     oder `null`), `nur_lokal` die Zahl der Fassungen, die im Remote noch fehlen
     (`git rev-list origin/<zweig>..HEAD`), `remote` die Adresse oder `null`,
     `lage` eine von `abgeglichen`, `nicht abgeglichen`, `kein remote`.
     Der Zeitpunkt darf im Speicher liegen; nach einem Neustart ist er `null`.
  4. Vor dem Lesen: `/board/data` versucht höchstens einmal je Minute einen
     Abgleich (die Seite fragt oft; ohne Bremse ginge jede Anfrage ins Netz). Ein
     gescheiterter Abgleich blockiert die Antwort nicht und lässt den lokalen Stand
     stehen.
  5. Nach dem Schreiben: eine Speicherung bleibt ganz oder gar nicht; wenn das
     Weitergeben scheitert, bleibt die Fassung lokal und `nur_lokal` zählt sie.
  6. Kopfzeile der Seite: „zuletzt abgeglichen ‹Zeit›“ bzw. „nicht abgeglichen“
     und bei Bedarf „n Fassungen nur hier“. Die Seite liest beides aus `stand`.
  7. Prüfskript `produkt/test/schritt04.mjs`: legt in `/tmp` ein nacktes
     Repository als `origin` an, klont es zweimal, lässt das Modul mit dem einen
     Klon und einer eigenen `board.config.json` laufen und prüft:
     - im zweiten Klon eine Datei ändern und festschreiben und schieben; im Modul
       `POST /board/sync` → die Änderung steht im ersten Klon, `stand.zeit` ist
       gesetzt, `nur_lokal` ist 0;
     - im Modul über eine schreibende Route speichern und `POST /board/sync` →
       die Fassung liegt im nackten `origin`;
     - `git remote remove origin` im ersten Klon; `/board/data` antwortet weiter,
       `stand.lage` ist `kein remote`, `stand.remote` ist `null`.
  8. Am Ende den Stand der Ablage als Fassung festhalten („Abgleich“), sodass
     `git status --porcelain` leer ist.
- **Ergebnis:** Route `/board/sync`; `stand` in `/board/data`; die Kopfzeile zeigt
  Zeit und Zahl; das Prüfskript belegt Holen, Geben und den Fall ohne Remote; eine
  Fassung mit dem Stand.
- **Prüfung:**
  ```
  node /workspace/projekte/board/vorgaenge/board-gesamtkonzept/produkt/test/schritt04.mjs   # Exit 0
  node /workspace/projekte/board/vorgaenge/board-gesamtkonzept/produkt/test/schritt03.mjs   # weiter Exit 0
  git -C /workspace/projekte/board status --porcelain                                        # leer
  git -C /workspace/projekte/board log -1 --format='%an %s'                                  # Thomas Heinrich, Abgleich
  ```
  Erwartet: das Prüfskript meldet die drei Lagen und endet mit Exit 0; der
  bestehende Schritt-03-Test läuft weiter; die Ablage ist festgehalten.
- **Hinweis:** Das echte Repository hat keinen `origin`. Das ist kein Fehler:
  Das Board sagt dann „kein remote“. Ein Remote wird nicht angelegt — dafür
  braucht es seine Adresse und seinen Zugang (im Bericht als offener Punkt).
- **Grenzen:** Kein Neustart. Kein Netz nach außen (nur lokale Repositories in
  `/tmp`). Kein Remote im echten Repository. Keine fremden Dateien außerhalb von
  `produkt/` und `arbeit/` ändern. Keine Rückfrage.

welcher Befehl, Exit-Code, entscheidende Zeile.
