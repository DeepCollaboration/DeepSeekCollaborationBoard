# Schritt 14 — GitHub-Client und Token

- **Ziel:** Das Plugin liest Repository-Metadaten, Sterne, Releases, offene Fragen und Pull Requests von GitHub und kann mit einem Token schreiben; der Token liegt sicher, und ohne Token bleiben die Leseabfragen.
- **Eingang:** `index.js` (Routenmuster, `ctx.webServer.register`, `leseKoerper`), `client.js` (Board-Leiste, Popover „Anzeige“; die Datei ist groß — gezielt mit `grep` die Stelle suchen und nur dort ändern), `boards.js` (`$DSH_HOME`, Dateirechte), `test/schritt24.mjs` (In-Process-Server).
- **Tun:**
  1. Lege `github.js` an, ohne zusätzliche Abhängigkeiten (`fetch` aus Node 24). Schnittstelle:
     - `GITHUB_API = process.env.DSH_GITHUB_API || 'https://api.github.com'` (die Umgebungsvariable ist nur für Prüfungen da).
     - `tokenPfad(home)`, `liesToken(home)`, `schreibeToken(home, token)`, `loescheToken(home)`: `$DSH_HOME/board/github.json`, Inhalt `{ "token": "…" }`, Datei `0600`, Verzeichnis `0700`, Schreiben über `.tmp` + `rename`. Der Token erscheint in keiner Antwort, keiner Fehlermeldung und keinem Log.
     - `erstelleClient({ home, token, basis, fetchImpl, cacheTtl = 60000, jetzt })` mit:
       `repo(owner, name)`, `releases(owner, name)`, `issues(owner, name, {state})` (Pull Requests ausfiltern), `pulls(owner, name, {state})`, `teams(org)`, `teamMitglieder(org, slug)`, `benutzer(login)`, `berechtigung(owner, name, login)`, `rateGrenze()`, `erstelleRepo(org, {name, privat, beschreibung, themen})`, `setzeSichtbarkeit(owner, name, privat)`, `erstellePull(owner, name, {titel, text, head, base})`, `erstelleIssue(owner, name, {titel, text})`, `erstelleFork(owner, name)`.
     - Normalisierte Antworten (nicht die rohe GitHub-Form): `repo` → `{name, vollerName, privat, sichtbarkeit, sterne, forks, offeneFragen, beschreibung, themen, standardZweig, adresse, gedrueckt, lizenz, archiviert, eigentuemer}`; `releases` → `{tag, name, datum, vorab}`; `issues`/`pulls` → `{nummer, titel, zustand, autor, adresse, erstellt, aktualisiert, zusammenGefuehrt}`.
     - Fehler als `GithubFehler` mit `status`, `repo`, `meldung`, `grenze` (Rest, Reset). 401 → „Token ungültig oder abgelaufen“; 403/429 mit `x-ratelimit-remaining: 0` → „GitHub-Grenze erreicht; wieder ab <ISO>“; 404 → „Repository … nicht gefunden oder nicht zugänglich“; Netzfehler → „GitHub nicht erreichbar“. 5xx einmal wiederholen.
     - Zwischenspeicher im Speicher je Client (TTL); Sterne zusätzlich in `$DSH_HOME/board/sterne.json` (`{ "<owner>/<repo>": { "sterne": n, "am": iso } }`). Ein abgelaufener oder fehlender Zwischenspeicher darf eine Leseabfrage nicht verhindern.
  2. Routen:
     - `GET /board/github/stand?repo=<owner/name>`: ohne `repo` → `{verbunden, login, grenze}` (Token prüfen mit `GET /user`, Fehler weich melden); mit `repo` → `{verbunden, repo, sterne, fassung, freigaben, fehler}`. `fassung` ist der jüngste Release-Tag oder `null`.
     - `POST /board/github/token` mit `{token}` oder `{loeschen: true}`: Token erst nach erfolgreichem `GET /user` speichern; Antwort `{verbunden, login}`. Ungültiger Token → 401, nichts gespeichert.
  3. Oberfläche: Im Popover „Anzeige“ ein Abschnitt „GitHub“ mit Status („nicht verbunden“ / „verbunden als <login>“), einem Passwortfeld und „Verbinden“, „Token löschen“; darunter ein Feld „Repository (owner/name)“ und „Prüfen“, das Sterne und letzte Fassung anzeigt. Ohne Token bleiben Lesen und Prüfen möglich; Schreibknöpfe erscheinen erst mit Token.
  4. `test/schritt31.mjs`: ein lokaler HTTP-Server (`node:http`, Port 0) als GitHub-Ersatz, `DSH_GITHUB_API` darauf gesetzt; geprüft werden Metadaten/Sterne, Releases, Issue-Filter, 404, 401, Rate-Limit, Zwischenspeicher (zweite Abfrage ohne zweiten Treffer), Token-Datei (0600, Inhalt, Löschen), Routen und dass der Token nirgends im Antworttext steht. Der Test räumt Server und Home ab.
- **Ergebnis:** `github.js`; Routen `/board/github/stand` und `/board/github/token`; der GitHub-Abschnitt in der Anzeige; `test/schritt31.mjs` grün; ohne Token liest und zeigt das Board, mit Token sagt es „verbunden“.
- **Prüfung:** `cd /workspace/projekte/board-plugin && node --test test/schritt31.mjs` → `ok GitHub: Sterne 7, Fassung v1.2.0; Token 0600, verbunden, gelöscht; 404/401/Grenze klar; Token nirgends im Text`. Danach `node --test` → 30 von 30; `node --check github.js`, `node --check index.js`, `node --check client.js` → je 0.
- **Grenzen:** Produktordner und `/tmp/board-scheibe1/`; kein echter GitHub-Aufruf in der Prüfung; keine Rückfrage; keine Commits; keine neuen Abhängigkeiten.
