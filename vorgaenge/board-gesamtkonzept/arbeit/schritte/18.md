# Schritt 18 — Beiträge als Pull Requests

- **Ziel:** Ein Beitrag ist ein Pull Request am Repository des Dings; das Board zeigt offene, zusammengeführte und abgelehnte Beiträge und verlinkt sie; ohne Token bleibt der Weg über GitHub.
- **Eingang:** Schritt 17; `github.js` (`erstellePull`, `pulls`); `index.js` (Routenmuster, `darfSchreiben` aus `rechte.js`); `client.js` (Stations-, Workflow- und Vorhaben-Einzelheit).
- **Tun:**
  1. `github.js` ergänzen: `pull(owner, name, nummer)` und `beitraege(owner, name, {state:'all'})` (offen, geschlossen, zusammengeführt); normalisiert `{nummer, titel, zustand, autor, adresse, erstellt, aktualisiert, zusammenGefuehrt, quelle, ziel}`.
  2. Routen:
     - `GET /board/github/beitraege?repo=<owner/name>`: liest die PRs; ohne Token nur, wenn das Repository öffentlich ist; sonst `{kann:false, adresse, hinweis}`.
     - `POST /board/github/beitrag` mit `{repo, titel, text, head, base}`: nur mit Token und Schreibrecht; `head` und `base` sind Pflicht (der Zweig wird vorher per Git geschickt); Antwort `{nummer, adresse}`; Fehler nennen das Repository. Ohne Token 409 mit `{kann:false, adresse, hinweis: 'Pull Request auf GitHub öffnen'}`. Kein lokaler Commit.
     - **Nur Repositories des offenen Boards.** Ein lokaler Ordner, eine Adresse oder ein `owner/name`, das nicht im Board (oder dessen Workflow/Vorhaben) vorkommt, wird mit 403 abgewiesen, bevor ein API-Aufruf geschieht. Die Prüfung löst den Bezug über die Verweise des Boards auf, nicht über den übergebenen Pfad allein.
     - `GET /board/github/beitrag?repo=&nummer=`: ein einzelner PR mit Zustand.
  3. Oberfläche: In der Einzelheit eines Vorhabens, einer Station und eines Workflows ein Abschnitt „Beiträge“: Liste mit Nummer, Titel, Zustand („offen“, „zusammengeführt“, „geschlossen“) und Verweis. Mit Token ein Knopf „Pull Request öffnen“ und ein kleines Formular (Titel, Text, Quellzweig, Zielzweig); ohne Token ein Verweis „Auf GitHub beitragen“. Ein zusammengeführter PR bleibt sichtbar; der neue Stand wird beim nächsten Öffnen gelesen.
  4. `test/schritt35.mjs`: nachgebildeter GitHub-Server mit PR anlegen, lesen, zusammenführen; Board der Fassung 2 mit einem Vorhaben an einer Station; geprüft werden: ohne Token 409 mit GitHub-Adresse und kein Knopfzustand (`kann:false`); mit Token PR anlegen (Nummer, Adresse), Liste zeigt „offen“, nach dem Zusammenführen „zusammengeführt“, ein abgelehnter PR bleibt „geschlossen“ sichtbar; kein Commit im lokalen Repository.
