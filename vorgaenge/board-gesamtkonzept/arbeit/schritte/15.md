# Schritt 15 — Speichern auf einem überholten Stand schreibt nicht

- **Ziel:** Wer eine Datei offen hat, während ein anderer sie ändert, überschreibt
  nichts; sein Text bleibt und wird als Beitrag angeboten.
- **Eingang:**
  - `/board/doc` mit `basis` (Schritt 03/11);
  - Beiträge (Schritt 11) und die Prüfstelle `darf` (Schritt 06);
  - `produkt/index.js`, `produkt/ablage.js`, `produkt/client.js`;
  - `architektur.md`, Abschnitte „Git“ (Basisprüfung) und „Ausfälle und Betrieb“
    („Beide ändern dasselbe“).
- **Tun:**
  1. `GET /board/doc` liefert zu jeder Datei `basis`: die Fassung, die zuletzt
     diese Datei geändert hat (Commit-Kennung; `null`, wenn die Datei noch nicht
     gefasst ist). Die `basis` ändert sich genau dann, wenn sich die Datei ändert —
     nicht, wenn anderswo im Repository etwas geschrieben wurde.
  2. `POST /board/doc/schreiben` prüft vor dem Schreiben: Ist eine `basis`
     mitgegeben und weicht sie von der aktuellen ab, wird **nicht** geschrieben.
     Antwort: `{ ok: false, neu: { text, basis } }` mit Status 409 und dem neuen
     Stand. Ohne `basis` wird wie bisher geschrieben.
  3. Nichts wird zusammengeführt. Der neue Stand kommt zurück, der eigene Text
     bleibt beim Aufrufer.
  4. Die Seite behält bei 409 den eigenen Text im Editor, sagt, dass der Stand
     neuer ist, und bietet an, den eigenen Text als Beitrag anzulegen (über
     `/board/beitrag` mit der neuen `basis`). Der Beitrag erscheint am Vorhaben wie
     jeder andere; die Datei im Vorhaben bleibt unverändert.
  5. Ein Schreiben mit richtiger `basis` geht durch und legt eine Fassung an (wie
     bisher); danach ist die neue `basis` die der Datei.
  6. Prüfskript `produkt/test/schritt15.mjs` auf einer Ablage-Kopie:
     - Datei mit `basis` öffnen → `basis` gesetzt; mit dieser `basis` speichern →
       ok, Datei geändert, neue Fassung, neue `basis` verschieden;
     - die Datei von außen ändern und festschreiben (anderer Urheber) → mit der
       alten `basis` speichern → 409, `neu.text` ist der neue Stand, `neu.basis`
       gesetzt, die Datei ist byte-gleich;
     - den eigenen Text über `/board/beitrag` als Beitrag anlegen → Beitrag liegt
       unter `beitraege/…` mit der neuen `basis`, die Datei ist unverändert;
     - mit der neuen `basis` speichern → geht durch;
     - zwei Schreibvorgänge auf denselben Stand: der zweite mit der alten `basis`
       → 409.
  7. Die Prüfskripte 02–14 grün halten.
  8. Am Ende den Stand der Ablage als Fassung festhalten („Überholter Stand“).
- **Ergebnis:** `basis` je Datei; die Prüfung vor dem Schreiben; der Weg „mein
  Text als Beitrag“; kein Zusammenführen; ein Prüfskript; eine Fassung.
- **Prüfung:**
  ```
  node .../produkt/test/schritt15.mjs   # Exit 0
  node .../produkt/test/schritt14.mjs   # Exit 0
  node .../produkt/test/schritt11.mjs   # Exit 0
  node .../produkt/test/schritt03.mjs   # Exit 0
  git -C /workspace/projekte/board status --porcelain          # leer
  git -C /workspace/projekte/board log -1 --format='%an %s'    # Thomas Heinrich, Überholter Stand
  ```
- **Grenzen:** Kein Neustart, kein Netz. Die echte Ablage bleibt unberührt (keine
  fremde Änderung, keine zweite Person) — die Prüfung arbeitet auf der Kopie.
  Keine fremden Dateien außerhalb von `produkt/` und `arbeit/` ändern. Keine
  Rückfrage.

Am Ende: Bericht nach `arbeit/schritte/15-bericht.md` — was gebaut, welche Dateien,
welcher Befehl, Exit-Code, entscheidende Zeile.
