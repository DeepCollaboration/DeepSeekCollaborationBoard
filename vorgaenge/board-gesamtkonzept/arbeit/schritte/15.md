# Schritt 15 — Öffentlich und privat

- **Ziel:** Jedes Repository trägt seine Sichtbarkeit; ein öffentliches Ding darf nur auf öffentliche Dinge verweisen; die Repositories lassen sich unter der Organisation anlegen und schicken; ohne Schreibrecht bleibt das Board im Lesemodus.
- **Eingang:** Schritt 14 (`github.js`); Schritt 13 (`/workspace/projekte/board-repos`, `sichtbarkeit.json`); `komposition.js`; `index.js` (Routen `/board/workflow/station`, `/board/vorhaben/verschieben`); `boards.js`.
- **Tun:**
  1. Lege `rechte.js` an:
     - `sichtbarkeitVon(home, pfad)`: liest zuerst `$DSH_HOME/board/sichtbarkeit.json` (absolute Pfade → `'öffentlich'|'privat'`), sonst die Datei `sichtbarkeit.json` im Elternordner des Repositories (Schlüssel = Ordnername; so trägt der Umzug seine Angabe mit), sonst entscheidet der Repo-Name (`vorhaben-*` und `board-team` privat, sonst öffentlich). Nichts wird stillschweigend in eine Datei geschrieben.
     - `pruefeVerweise(boardPfad, {home})`: geht die Verweise des Boards, seiner Workflows und Vorhaben durch; ein öffentliches Ding, das auf ein privates verweist, ergibt `{art: 'sichtbarkeit', von, auf, grund}`. Liefert `{luecken, sichtbarkeiten}`. Die Lücken werden an die vorhandenen `luecken` der Komposition angehängt, nicht ersetzt.
     - `darfSchreiben({pfad, home, client})`: lokal ohne Remote → wahr; mit Remote und ohne Token → falsch; mit Token über `berechtigung` (`admin`, `maintain`, `push`, `write`) → wahr. Das Ergebnis wird je Repository kurz zwischengespeichert.
  2. `komposition.js` ergänzt am Ergebnis `luecken` und je Station/Workflow/Vorhaben `sichtbarkeit`; die vorhandenen Felder bleiben. `/board/data` gibt beides weiter.
  3. `POST /board/workflow/station`: Ist der Workflow öffentlich und die Station privat, antwortet die Route 409 „Öffentlich verweist nur auf Öffentliches“, ohne Commit. Dasselbe gilt für ein öffentliches Board, das einen privaten Workflow aufnehmen will (`/board/workflow/verbinden`).
  4. `POST /board/github/veroeffentlichen` mit `{board}`:
     - ohne Token: 409 mit `befehle` (je Repository `git -C <pfad> remote add origin <url>` und `git -C <pfad> push -u origin main --tags`) und `organisation`;
     - mit Token: je Repository `erstelleRepo` (existiert es, verbinden), Remote setzen (`git@github.com:<org>/<repo>.git`; `DSH_GIT_REMOTE_BASIS` ersetzt in Prüfungen den Anfang, z. B. `file:///tmp/board-scheibe1/schritt32/remotes`), `git push -u origin main --tags`, Sichtbarkeit über `setzeSichtbarkeit`; Fehler nennen das Repository und halten an; Antwort `{veroeffentlicht, fehler}`.
     - Vor dem ersten Schreiben wird `pruefeVerweise` geprüft; eine Lücke bricht mit 409 ab.
  5. Oberfläche: In der Anzeige steht je Board „öffentlich“ oder „privat“ und ein Knopf „Veröffentlichen“; ohne Token zeigt er die Befehle zum Kopieren, mit Token ruft er die Route. Lücken erscheinen als Zeile „Öffentlich verweist auf Privates: …“ an der Bibliothek und am Board; Schreibknöpfe fehlen, wenn `darf` falsch ist (das ist vorhanden, wird aber für Fassung 2 geprüft).
  6. `test/schritt32.mjs`: Prüffläche mit fünf Repositories, Sichtbarkeitskarte im Home; Server in-process; geprüft werden Lücken, 409 beim Eintragen einer privaten Station in einen öffentlichen Workflow (kein Commit), erlaubter Fall nach Umschalten auf öffentlich, Veröffentlichen ohne Token (409, Befehle), mit nachgebildetem GitHub und `DSH_GIT_REMOTE_BASIS` auf lokale Bare-Repositories (Remote gesetzt, gepusht, Sichtbarkeit gesetzt), Lesemodus bei Remote ohne Token (`darf: false`, Verschieben 403).
- **Ergebnis:** `rechte.js`; Sichtbarkeit und Lücken in `/board/data`; abweisende Routen; Veröffentlichen-Route und Knopf; `test/schritt32.mjs` grün.
- **Prüfung:** `cd /workspace/projekte/board-plugin && node --test test/schritt32.mjs` → `ok Sichtbarkeit: Lücke erkannt, Schreiben abgewiesen, ohne Token Befehle, mit Token gepusht, Lesemodus`. Danach `node --test` → 31 von 31; `node --check rechte.js`, `node --check index.js`, `node --check client.js` → je 0.
- **Grenzen:** Produktordner und `/tmp/board-scheibe1/`; kein echter GitHub-Aufruf; keine Rückfrage; keine Commits; die echten neuen Repositories werden nicht verändert (Prüfung kopiert sie).
