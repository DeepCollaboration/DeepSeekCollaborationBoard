# Schritt 11 — Am fremden Vorhaben speichert der Editor als Beitrag

- **Ziel:** Wer nicht verantwortet, schreibt nicht in das fremde Vorhaben, sondern
  legt einen Beitrag an: eine Notiz und, wenn nötig, eine geänderte Fassung der
  Datei. Das Original bleibt unberührt.
- **Eingang:**
  - fremdes Vorhaben und Leser (Schritt 07);
  - `beitraege/` in der Ablage (Schritt 03, bisher leer);
  - Verantwortliche und Prüfstelle `darf` (Schritt 06);
  - `produkt/index.js`, `produkt/ablage.js`, `produkt/client.js`;
  - `architektur.md`, Abschnitte „Ablage im Repository“ (`beitraege/…`) und
    „Bausteine“ (Beiträge).
- **Tun:**
  1. Neue Route `POST /board/beitrag`: `{ vorhaben, schritt, notiz, dateien }` →
     `{ ok, beitrag }`. Sie legt
     `beitraege/<vorhaben>/<beitrag>.json` an mit
     `{ id, vorhaben, schritt, von, seit, basis, notiz, dateien, entschieden }`:
     `von` ist die eigene Person, `seit` der Zeitpunkt, `basis` die Fassung, auf
     der der Vorschlag aufsitzt, `dateien` eine Liste `{ name, datei }`,
     `entschieden` ist `null`.
  2. Die vorgeschlagene Fassung jeder Datei liegt unter
     `beitraege/<vorhaben>/<beitrag>/<datei>.md`. Fehlt sie, ist der Beitrag nur
     eine Notiz.
  3. Die Originaldatei im Vorhabenordner wird nicht geschrieben; der Beitrag ist
     für jeden möglich, der das Board sieht — er hängt nicht an `darf.aendern`.
     Mindestens eine Notiz oder eine Datei muss da sein; ein leerer Beitrag wird
     abgewiesen.
  4. Jeder Beitrag wird als Fassung festgehalten (Urheber: der Beitragende).
  5. `/board/data` liefert `beitraege`: je Beitrag sein Ort (Vorhaben, Station),
     der Name des Beitragenden, Zeitpunkt, Notiz und die Namen der vorgeschlagenen
     Dateien.
  6. Der Beitrag erscheint in der Seite an der Station mit dem Namen des
     Beitragenden und lässt sich öffnen (Notiz und vorgeschlagene Fassungen lesen).
  7. Im Leser eines fremden Vorhabens öffnet „Bearbeiten“ den Text; gespeichert
     wird nicht in die Originaldatei, sondern über „Als Beitrag speichern“ mit
     Notiz. Der Bearbeiten-Knopf führt dort also zum Beitrag, nicht zum Schreiben.
  8. Prüfskript `produkt/test/schritt11.mjs` auf einer Ablage-Kopie mit `p2` und
     einem fremden Vorhaben mit `vision.md`:
     - ein Beitrag mit geänderter `vision.md` und Notiz wird angelegt: JSON mit
       allen Feldern, die vorgeschlagene Fassung liegt unter `beitraege/…`, das
       Original ist byte-gleich, die Fassung nennt „Thomas Heinrich“;
     - `/board/data` zeigt den Beitrag mit `von: "Thomas Heinrich"`, der Notiz und
       dem Dateinamen, an Station und Vorhaben;
     - ein Beitrag nur mit Notiz wird angenommen, ein ganz leerer mit 400
       abgewiesen;
     - die fremde `vorhaben.json` ist byte-gleich.
  9. Die Prüfskripte 02–10 grün halten.
  10. Am Ende den Stand der Ablage als Fassung festhalten („Beiträge“).
- **Ergebnis:** die Route `/board/beitrag`; Beitragsdateien mit Notiz und
  vorgeschlagenen Fassungen; `beitraege` in `/board/data`; der Leser bietet
  Bearbeiten als Beitrag; das Original bleibt unberührt; ein Prüfskript; eine
  Fassung.
- **Prüfung:**
  ```
  node .../produkt/test/schritt11.mjs   # Exit 0
  node .../produkt/test/schritt10.mjs   # Exit 0
  node .../produkt/test/schritt07.mjs   # Exit 0
  node .../produkt/test/schritt03.mjs   # Exit 0
  ls /workspace/projekte/board/beitraege 2>/dev/null   # leer oder fehlt: echte Ablage ohne Beiträge
  git -C /workspace/projekte/board status --porcelain          # leer
  git -C /workspace/projekte/board log -1 --format='%an %s'    # Thomas Heinrich, Beiträge
  ```
- **Grenzen:** Kein Neustart, kein Netz. Die echte Ablage bekommt keinen Beitrag
  und keine zweite Person — beides lebt in der Prüfkopie. Keine fremden Dateien
  außerhalb von `produkt/` und `arbeit/` ändern. Keine Rückfrage.

welcher Befehl, Exit-Code, entscheidende Zeile.
