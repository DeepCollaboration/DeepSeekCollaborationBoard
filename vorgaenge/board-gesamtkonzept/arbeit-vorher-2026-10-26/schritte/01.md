# Schritt 01 — Das Board wird ein Produkt dieses Vorhabens

- **Ziel:** Das laufende Board-Plugin liegt vollständig und unverändert im Ordner
  dieses Vorhabens unter `produkt/`; der Harness lädt es von dort.
- **Eingang:**
  - `/workspace/plugins/dsh-board/` — das heute geladene Plugin (7 Dateien:
    `package.json`, `index.js`, `client.js`, `cordis.patch.yml`, `locale/de.json`,
    `locale/en.json`, `icon.svg`).
  - `/workspace/projekte/board/vorgaenge/board-gesamtkonzept/architektur.md`,
    Abschnitt „Harness“.
- **Tun:**
  1. `produkt/` im Vorhabenordner anlegen.
  2. Den gesamten Inhalt von `plugins/dsh-board/`, einschließlich `locale/`, nach
     `produkt/` kopieren. Nichts auslassen, nichts umschreiben.
  3. Die Kopie gegen das Original prüfen: gleiche Dateiliste, gleicher Inhalt,
     gleiche Dateigrößen.
  4. Prüfen, dass die Exporte in `produkt/package.json` auf vorhandene Dateien
     zeigen (`node -e`-Einzeiler genügt).
  5. Den bisherigen Ordner `plugins/dsh-board/` nicht verändern und nicht löschen.
- **Ergebnis:** `produkt/` mit allen 7 Dateien; der Inhalt ist byte-gleich mit dem
  Original.
- **Prüfung:**
  ```
  diff -r /workspace/plugins/dsh-board \
          /workspace/projekte/board/vorgaenge/board-gesamtkonzept/produkt
  find /workspace/projekte/board/vorgaenge/board-gesamtkonzept/produkt -type f
  node -e "const p=require('/workspace/projekte/board/vorgaenge/board-gesamtkonzept/produkt/package.json'); for (const v of Object.values(p.exports)) { const {statSync}=require('fs'); const path=require('path'); const f=path.join('/workspace/projekte/board/vorgaenge/board-gesamtkonzept/produkt', v.replace(/^\.\//,'')); statSync(f); console.log('ok', v); }"
  ```
  Erwartet: `diff` ohne Ausgabe und Exit 0; `find` zählt 7 Dateien; die
  Export-Prüfung meldet `ok` für `.`, `./client`, `./locale/*.json`, `./icon`
  (bei `./locale/*.json` genügt, dass `locale/` existiert — dann den Eintrag
  überspringen und stattdessen `locale/de.json` und `locale/en.json` prüfen).
- **Grenzen:** nur `produkt/` anlegen und füllen. `plugins/dsh-board/` nicht
  ändern, nicht löschen. Das Harness-Profil (`/dsh-home`) nicht anfassen — der
  Verweis auf das neue Verzeichnis wird von der Bauleitung gesetzt. Keine
  Rückfrage. Keine Commits.

Am Ende: kurzer Bericht nach `arbeit/schritte/01-bericht.md` — was kopiert wurde,
welche Dateien, welcher Befehl lief, welcher Exit-Code, die entscheidende Zeile.
Keine Zusammenfassung des Wegs.
