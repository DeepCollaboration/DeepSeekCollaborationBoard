# Schritt 10 — Der Skill der anderen Person läuft in meinem Harness

- **Ziel:** Ein Vorhaben an einem fremden Schritt kann dessen Skill im eigenen
  Harness ausführen; die Anweisung kommt mit der Ablage, das Transkript bleibt beim
  eigenen Vorhaben.
- **Eingang:**
  - der Verweis im eigenen Workflow (Schritt 09), aufgelöst mit `host` und `skill`;
  - `skills/<host>/<schritt>.md` (Schritt 08);
  - `produkt/index.js` (Route `/board/gespraech/senden`, das Einsetzen aus
    Schritt 08, `/board/skill/lauf`), `produkt/client.js`;
  - `architektur.md`, Abschnitte „Harness“ (Skills, Sitzungen) und „Rechte und
    Sicherheit“ (fremde Schritte sind fremde Anweisungen).
- **Tun:**
  1. Beim Start an einem Verweis-Schritt den Skill des Hosts aus der Ablage lesen
     (`skills/<host>/<schritt>.md`), als `<host>-<schritt>` in `$DSH_HOME/skills`
     einsetzen (Frontmatter `name` = `<host>-<schritt>`), die Sitzung im eigenen
     Arbeitsbereich mit diesem Namen starten und den Einsatz danach wieder
     wegnehmen — auch bei einem gescheiterten Start.
  2. Die fremde Workflow-Datei und die fremde Skill-Datei werden dabei nur gelesen,
     nie geschrieben. Die Sitzung läuft im eigenen Arbeitsbereich.
  3. Der Startauftrag nennt den eingesetzten Namen; das Gespräch folgt der
     Anweisung aus der Ablage, nicht dem Chat.
  4. Das Transkript wird wie bei einem eigenen Schritt unter
     `vorgaenge/<eigenes>/transkripte/` abgelegt und am Schritt geführt
     (`laeufe`); die Fassung trägt den eigenen Urheber. `git -C
     /workspace/projekte/board status` ist nach dem Lauf ruhig, weil die Fassung
     festgehalten wurde.
  5. Die Seite bietet den Start an einem Verweis-Schritt an, wenn das eigene
     Vorhaben dort steht und die eigene Person verantwortet.
  6. Prüfskript `produkt/test/schritt10.mjs` mit eigener Ablage-Kopie, eigener
     `board.config.json`, eigenem `DSH_HOME` und ersetztem Sitzungsdienst:
     - ein eigenes Vorhaben steht auf der Verweis-Position zu einem p2-Schritt mit
       `skills/p2/pruefen.md`;
     - der Start setzt während des Aufrufs `$DSH_HOME/skills/p2-pruefen/SKILL.md`
       ein; der Ersatz prüft den Inhalt (gleich der p2-Anweisung) und den Namen im
       Startauftrag; nach dem Aufruf ist der Ordner weg;
     - der Transkript-Aufruf legt die Datei unter
       `vorgaenge/<eigenes>/transkripte/` an, sie erscheint in `laeufe`, die
       Fassung nennt „Thomas Heinrich“;
     - `workflows/p2.json` und `skills/p2/pruefen.md` sind byte-gleich, die
       fremde `vorhaben.json` gibt es nicht;
     - ein Start an einem fremden Schritt auf einem **fremden** Vorhaben antwortet
       403.
  7. Die Prüfskripte 02–09 grün halten.
  8. Am Ende den Stand der Ablage als Fassung festhalten („Fremder Skill-Lauf“).
- **Ergebnis:** ein Lauf an einem Verweis-Schritt mit der Anweisung aus der Ablage;
  Einsatz und Wegnahme unter `<host>-<schritt>`; Transkript im eigenen Vorhaben;
  fremde Dateien unverändert; ein Prüfskript; eine Fassung.
- **Prüfung:**
  ```
  node .../produkt/test/schritt10.mjs   # Exit 0
  node .../produkt/test/schritt09.mjs   # Exit 0
  node .../produkt/test/schritt08.mjs   # Exit 0
  node .../produkt/test/schritt07.mjs   # Exit 0
  node .../produkt/test/schritt03.mjs   # Exit 0
  ls /dsh-home/skills                   # unverändert, kein p2-*
  git -C /workspace/projekte/board status --porcelain          # leer
  git -C /workspace/projekte/board log -1 --format='%an %s'    # Thomas Heinrich, Fremder Skill-Lauf
  ```
- **Grenzen:** Kein Neustart, kein Netz, keine echte Sitzung und keine echte
  Modellanfrage — der Sitzungsdienst wird im Prüfskript ersetzt. Die echte Ablage
  bekommt keinen fremden Schritt und keine zweite Person. `$DSH_HOME/skills` der
  echten Installation nicht verändern. Keine Rückfrage.
