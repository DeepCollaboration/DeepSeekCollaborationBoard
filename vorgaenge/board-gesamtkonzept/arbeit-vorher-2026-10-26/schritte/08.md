# Schritt 08 — Der Skill eines Schritts liegt in der Ablage

- **Ziel:** Ein Schritt trägt seine Anweisung als Datei in der Ablage; wer ihn
  benutzt, legt sie für den Lauf unter dem Namen ihres Hosts im Harness ab und
  nimmt sie danach wieder weg.
- **Eingang:**
  - `skills/<person>/<schritt>.md` als Ort der Anweisung (bisher leer, Architektur
    „Ablage im Repository“);
  - `$DSH_HOME/skills/<name>/SKILL.md` — die heute installierten Anweisungen
    (u. a. `grillme-vision`, `grillme-fachkonzept`,
    `architekturentscheidungen`, `bauplan-erstellen`, `umsetzen`);
  - `workflows/p1.json` — die Schritte tragen `skill` (Schritt 03);
  - `produkt/index.js` (Routen `/board/skills`, `/board/skill/dateien`,
    `/board/skill/eintragen`, `/board/gespraech/senden`, `/board/skill/lauf`),
    `produkt/client.js`;
  - `architektur.md`, Abschnitte „Bausteine“ (Schritt-Skills) und „Harness“.
- **Tun:**
  1. Einmalige Übernahme: Für jeden Schritt mit `skill` in `workflows/p1.json` die
     heutige Anweisung aus `$DSH_HOME/skills/<skill>/SKILL.md` nach
     `skills/p1/<schritt>.md` übernehmen (fünf Dateien: `idee-vision`,
     `vision-fachkonzept`, `fachkonzept-architektur`, `architektur-umsetzung`,
     `umsetzen`). Nichts verschieben, `$DSH_HOME/skills` bleibt unverändert.
  2. Die Ablage ist die Quelle: Lesen, Anzeigen und Ändern einer Schritt-Anweisung
     arbeiten auf `skills/<person>/<schritt>.md`, nicht auf `$DSH_HOME/skills`.
  3. Beim Start eines Laufs an einem Schritt: die Datei als
     `$DSH_HOME/skills/<host>-<schritt>/SKILL.md` einsetzen, mit Frontmatter
     `name: <host>-<schritt>` (damit der Harness sie unter diesem Namen findet);
     die Sitzung mit diesem Namen starten; nach dem Start wieder entfernen, auch
     wenn der Start scheitert. Der Ordner `$DSH_HOME/skills` selbst bleibt.
  4. Die Werkstatt schreibt ihre Änderung an einer Schritt-Anweisung in die Ablage
     und hält sie als Fassung fest; die Anzeige listet die Schritte mit ihrer
     Anweisung, nicht die installierten Fremdskills.
  5. Das Transkript entsteht wie bisher unter `vorgaenge/<ordner>/transkripte/` und
     erscheint am Schritt.
  6. Prüfskript `produkt/test/schritt08.mjs` mit eigenem `DSH_HOME` unter `/tmp`:
     - `skills/p1/` enthält die fünf Dateien, jede mit Frontmatter `name`,
       `description`, `whenToUse`;
     - `/board/skills` listet die fünf Schritte aus der Ablage;
     - ein Lauf an `idee-vision` (Sitzungsdienst im Prüfskript ersetzt) legt
       während des Starts `$DSH_HOME/skills/p1-idee-vision/SKILL.md` an — der
       Ersatz liest die Datei und notiert ihren Namen; nach dem Aufruf ist der
       Ordner wieder weg;
     - ein gescheiterter Start hinterlässt keinen Ordner;
     - eine Änderung über die Werkstatt-Route schreibt `skills/p1/<schritt>.md`
       und erzeugt eine Fassung mit Urheber;
     - `$DSH_HOME/skills/grillme-vision/SKILL.md` bleibt in der Kopie unverändert
       (die Prüfung arbeitet mit einer Kopie des Harness-Skillordners).
  7. Die Prüfskripte 02–07 grün halten.
  8. Am Ende den Stand der Ablage als Fassung festhalten („Schritt-Skills“).
- **Ergebnis:** `skills/p1/` mit fünf Anweisungen; die Ablage als Quelle für
  Lesen, Ändern und Starten; Einsetzen und Wegnehmen unter `<host>-<schritt>`;
  das Transkript bleibt; ein Prüfskript; eine Fassung.
- **Prüfung:**
  ```
  ls /workspace/projekte/board/skills/p1        # 5 Dateien
  node .../produkt/test/schritt08.mjs           # Exit 0
  node .../produkt/test/schritt07.mjs           # Exit 0
  node .../produkt/test/schritt06.mjs           # Exit 0
  node .../produkt/test/schritt05.mjs           # Exit 0
  node .../produkt/test/schritt04.mjs           # Exit 0
  node .../produkt/test/schritt03.mjs           # Exit 0
  node .../produkt/test/schritt02.mjs           # Exit 0
  ls /dsh-home/skills                           # unverändert, kein p1-*
  git -C /workspace/projekte/board status --porcelain          # leer
  git -C /workspace/projekte/board log -1 --format='%an %s'    # Thomas Heinrich, Schritt-Skills
  ```
- **Grenzen:** Kein Neustart, kein Netz, keine echte Sitzung (der Sitzungsdienst
  wird im Prüfskript ersetzt). `$DSH_HOME/skills` der echten Installation nicht
  verändern. Keine fremden Dateien außerhalb von `produkt/`, `arbeit/` und
  `skills/` in der Ablage ändern. Keine Rückfrage.

welcher Befehl, Exit-Code, entscheidende Zeile.
