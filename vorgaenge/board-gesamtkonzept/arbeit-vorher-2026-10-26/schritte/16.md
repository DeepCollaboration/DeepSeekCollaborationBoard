# Schritt 16 — Zwei Programmfassungen schreiben nicht gegeneinander

- **Ziel:** Hat die Ablage eine neuere Form als das eigene Programm, schreibt es
  nicht, sondern sagt es und nennt die Fassung, die die Ablage verlangt.
- **Eingang:**
  - `format` in der Ablage (`1`, Schritt 03);
  - die Formatprüfung in `produkt/ablage.js` (Schritt 03);
  - Abgleich (Schritt 04), `/board/data` und `produkt/client.js`;
  - `architektur.md`, Abschnitte „Ablage im Repository“ (`format`) und
    „Ausfälle und Betrieb“ („Zwei Programmfassungen“).
- **Tun:**
  1. Das Programm hat eine eigene Fassung (`FORMAT` = 1) und liest die Fassung der
     Ablage. `/board/data` liefert beide: `format` (die des Programms) und
     `formatAblage` (die der Ablage).
  2. Beim Lesen bleibt die Seite benutzbar; sie zeigt, wenn die Ablage neuer ist,
     einen Hinweis mit beiden Zahlen und dem Satz, dass dieses Board nicht schreibt,
     bis es aktualisiert ist.
  3. Vor jedem Schreiben wird verglichen. Ist die Ablage neuer, wird nicht
     geschrieben; die Antwort ist ein Fehler mit Status 409, der die verlangte
     Fassung nennt (Text enthält die Zahl der Ablage). Das gilt für alle
     schreibenden Routen, die über die Ablage gehen — nicht nur für eine.
  4. Ist die Ablage älter als das Programm, schreibt es ebenfalls nicht und sagt,
     dass die Ablage den Umzug braucht.
  5. Prüfskript `produkt/test/schritt16.mjs` auf einer Ablage-Kopie:
     - `format` auf `2` setzen → `/board/data` antwortet weiter und nennt `format:
       1`, `formatAblage: 2`;
     - ein Schreiben (Datei speichern und ein Vorhaben verschieben) → 409, der
       Text nennt `2`, die Datei und das Vorhaben bleiben unverändert, es entsteht
       keine neue Fassung, `git status` ist an der Kopie ruhig;
     - `format` zurück auf `1` → dieselben Schreibvorgänge gehen durch;
     - `format` auf `0` (älter) setzen → Schreiben wird abgewiesen und nennt den
       Umzug.
  6. Die Prüfskripte 02–15 grün halten.
  7. Am Ende den Stand der Ablage als Fassung festhalten („Fassungen“).
- **Ergebnis:** beide Fassungen in `/board/data`; der Hinweis in der Seite; die
  Prüfung vor jedem Schreiben mit 409 und genannter Fassung; ein Prüfskript; eine
  Fassung.
- **Prüfung:**
  ```
  node .../produkt/test/schritt16.mjs   # Exit 0
  node .../produkt/test/schritt15.mjs   # Exit 0
  node .../produkt/test/schritt04.mjs   # Exit 0
  node .../produkt/test/schritt03.mjs   # Exit 0
  test "$(cat /workspace/projekte/board/format)" = 1     # echte Ablage unverändert
  git -C /workspace/projekte/board status --porcelain          # leer
  git -C /workspace/projekte/board log -1 --format='%an %s'    # Thomas Heinrich, Fassungen
  ```
- **Grenzen:** Kein Neustart, kein Netz. Die echte Ablage bleibt auf `format` 1 —
  die höhere Zahl lebt nur in der Prüfkopie. Keine fremden Dateien außerhalb von
  `produkt/` und `arbeit/` ändern. Keine Rückfrage. **Schreibe kein Urteil in
  `arbeit/pruefung.md`** — das tut der Prüfer.

Am Ende: Bericht nach `arbeit/schritte/16-bericht.md` — was gebaut, welche Dateien,
welcher Befehl, Exit-Code, entscheidende Zeile.
