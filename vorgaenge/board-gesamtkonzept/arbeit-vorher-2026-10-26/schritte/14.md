# Schritt 14 — Der Rücksprung steht am Vorhaben

- **Ziel:** Ein offener Punkt schickt ein Vorhaben an einen früheren Schritt
  zurück; der Grund steht am Vorhaben, bis es wieder daran vorbei ist.
- **Eingang:**
  - `rueckkehr` in `vorgaenge/<ordner>/vorhaben.json` (Schritt 03);
  - `/board/vorhaben/zurueckschicken` und das Weitergeben (Schritt 06);
  - `produkt/index.js`, `produkt/ablage.js`, `produkt/client.js`;
  - `architektur.md`, Abschnitt „Ablage im Repository“ (`rueckkehr`).
- **Tun:**
  1. Zurückschicken (`/board/vorhaben/zurueckschicken`) trägt am Vorhaben
     `{ von, nach, grund, seit, erledigt: false }` ein und setzt die Station auf
     `nach`. Es geht durch dieselbe Prüfstelle (`darf(…, "zurueckschicken")`),
     verlangt einen Grund und eine vorhandene Zielstation.
  2. Das Weiterziehen über die Zielstation hinaus setzt offene Rücksprünge auf
     `erledigt: true`. Der Eintrag bleibt in der Datei stehen.
  3. `/board/data` liefert je Vorhaben die Rücksprünge samt Zielnamen und Grund;
     die Seite zeigt nur die offenen (`erledigt: false`) mit Ziel und Grund am
     Vorhaben. Ist einer erledigt, verschwindet er aus der Anzeige, nicht aus der
     Datei.
  4. Ein Rücksprung lässt die Verantwortung an der Zielstation beim bisherigen
     Verantwortlichen, wenn niemand genannt wird (wie beim Weitergeben).
  5. Prüfskript `produkt/test/schritt14.mjs` auf einer Ablage-Kopie mit einem
     eigenen Vorhaben an einer späteren Station:
     - zurückschicken an eine frühere Station mit Grund → das Vorhaben steht dort,
       `rueckkehr` trägt `{ von, nach, grund, seit, erledigt: false }`,
       `/board/data` zeigt den offenen Rücksprung mit Ziel und Grund;
     - ohne Grund → 400, ohne vorhandene Zielstation → 400;
     - Weiterziehen auf eine Station hinter dem Ziel → `erledigt: true` in der
       Datei, nicht mehr in der offenen Anzeige;
     - ein fremdes Vorhaben zurückschicken → 403, nichts geändert.
  6. Die Prüfskripte 02–13 grün halten.
  7. Am Ende den Stand der Ablage als Fassung festhalten („Rücksprung“).
- **Ergebnis:** der Vermerk am Vorhaben, seine Anzeige nur solange offen, die
  Erledigung beim Vorbeiziehen; ein Prüfskript; eine Fassung.
- **Prüfung:**
  ```
  node .../produkt/test/schritt14.mjs   # Exit 0
  node .../produkt/test/schritt13.mjs   # Exit 0
  node .../produkt/test/schritt06.mjs   # Exit 0
  node .../produkt/test/schritt03.mjs   # Exit 0
  git -C /workspace/projekte/board status --porcelain          # leer
  git -C /workspace/projekte/board log -1 --format='%an %s'    # Thomas Heinrich, Rücksprung
  ```
- **Grenzen:** Kein Neustart, kein Netz. Die echte Ablage bekommt keinen
  Rücksprung und keine zweite Person — das lebt in der Prüfkopie. Keine fremden
  Dateien außerhalb von `produkt/` und `arbeit/` ändern. Keine Rückfrage.

Am Ende: Bericht nach `arbeit/schritte/14-bericht.md` — was gebaut, welche Dateien,
welcher Befehl, Exit-Code, entscheidende Zeile.
